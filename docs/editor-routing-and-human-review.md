# 外部编辑器路由与人工审片设计

0.6更新：用户明确要求章节期间暂停口播，先准备带前后原声语境的独立章节停顿小样，再只确认新的声音与衔接；用户已回复认可。保留原画风和1.8秒时长的确认，不重问是否暂停，也不把旧连续原声批准扩展为新声音批准。源语音完整保留，后续字幕和动效按同一映射后移；实测与尚未接入的草稿边界见 [chapter-insertion.md](chapter-insertion.md)。

研究日期：2026-10-01。本文描述总插件的设计；本轮0.3已经实现纯路由和本地审片状态模块，外部编辑调度与ChatCut实测尚未完成。读取了当前ChatCut研究、intake规则、适配器登记、主skill，以及本机ChatCut 1.10.14的口播、验证和导出技能。用户截图确认插件已安装启用，当前旧会话工具清单未暴露ChatCut工具；连接状态与安装状态分别记录。

## 1. 大插件负责导演和制片，外部插件负责执行

Jed Video System 应成为编排插件，拥有素材审核、用户意图、具体剪辑计划、时钟映射、审片证据和交付记录。ChatCut、剪映 MCP / CLI、Remotion、Video Use 与声音 skill 保持各自独立安装。主插件在进入某个环节时发现实际能力，读取对应技能并调用已有入口；不把第三方引擎、账号、运行时和全部 skills 复制进公共仓库。

不能只靠“装了某插件”决定路线。每个适配器需要记录本次会话能读、能写、能预览、能导出什么，以及 hosted / desktop、输入格式、实际输出格式、素材传输方式、生成收费条件和验证证据。安装信息是线索，可调用工具和实测读回才是当前能力。

主插件新增的价值应是：知道何时剪、何时不剪、何时让用户看一个具体结果，保证换执行器后仍保留用户表达与教程步骤。接入任意编辑器都不应绕开这些约束。

## 2. 哪些替代，哪些保留，哪些条件启用

| 环节 | 推荐路线 | 替代与保留的边界 |
| --- | --- | --- |
| 素材审核与分段 | Jed 核心，使用本地源文件、转录和实际帧 | 必须保留。文件名、转录文字和编辑器自动分析都不能独立证明口播 / 录屏分类和讲解对应关系。 |
| 问询与人工审核 | Jed 核心 | 必须保留。外部编辑器负责展示和修改，审批依据、范围及版本由 Jed 统一记录。 |
| 口播精修 | 优先试验 ChatCut 文字稿与脚本编辑 | 可接管尚未实现的执行环节。Jed 仍决定候选、语义边界、保留项和审核范围。先短样实测，再启用批量。 |
| 转录 | 本地 Video Use 默认保留；ChatCut 路线按其实际接口需要转录 | 不进行双份“真值”维护。比较准确率、词边界和编辑能力后选本项目主转录；不同 word ID 不可混用。目前没有直接复用 WhisperX JSON 的接口证据。 |
| 字幕 | ChatCut 时间线可执行；本地路线用现有字幕计划和剪映字幕 | 可替代生成与样式执行，不替代人工修正文字。修字幕不等于改口播声音。先完成剪辑，再对齐字幕。 |
| 品牌固定文字与信息动效 | Remotion 保留 | 已验证的 A 版组件、统一 token、可复现透明层继续复用。ChatCut 可以用相同内容协议另写适配组件，不能把 TSX 直接视为其图形 JSX。 |
| 新视觉试验与可编辑图形 | ChatCut 或 Remotion，必要时 agy 提供设计建议 | 条件启用。先用真实画面做一个代表性小样，再决定扩大。agy 是视觉协作能力，不能代替用户接受结果。 |
| B-roll | Jed 定位与约束，编辑器执行 | 条件启用。复用录屏不加 B-roll 的明确偏好；口播 B-roll 不自动开启。素材来源、真实性和覆盖位置需审核。 |
| 音效与配乐 | 既有声音 skill 制定策略，剪映 / ChatCut 执行 | 保留声音策略。先复用本地素材；生成收费音频、替换人声或数字人均属独立授权事项。 |
| 可编辑审片 | ChatCut 当前项目或剪映时间线，辅以本地短片 | ChatCut 可补当前 MP4 预览的编辑能力，但工具写入成功不等于实际可看。审片以最终合成画面和声音为准。 |
| 剪映可编辑交付 | 保留现有 worker / Bridge；Desktop 路线另行实测 | 当前已有结构验证，应用播放仍待验证。ChatCut hosted 的 XML 不是剪映草稿；Desktop 草稿能力、字体和透明效果需独立确认。 |
| 成片导出 | 本次项目选定的编辑器或 Remotion | 一个主要交付路线。导出后做媒体与内容检查；不可把渲染成功当作审美批准或可编辑交付完成。 |

推荐先增加 ChatCut 的“短样精修 + 字幕同步 + 可编辑审片”适配器，验证一个清晰停顿的压缩。不要第一轮同时切换转录、动效、音效和工程交付，否则出现节奏或同步问题很难确定来源。

## 3. 一个项目，一份当前主时间线

第一种模式是 Jed 的 edit-plan 为主，Remotion 和剪映是该计划的投影。第二种模式是 ChatCut 为主编辑器，执行语义剪辑后读取实际片段与时长，把确认后的结果转换为 Jed 归一化时间表，再产生后续投影。项目需明确当前模式；不能把两个编辑器同时当作可独立写入的主状态。

换主编辑器要做一次明确交接：保存来源哈希、主转录版本、源区间到输出区间的映射、字幕内容、轨道角色和可转移 / 需烘焙 / 无法转移的元素。复制主项目的 MP4 只是平面视频，不是结构交接。若接口不能可靠读出结构，就保留在原编辑器执行，或明确限定为渲染交付。

当前编译器只支持单源、1 倍速、顺序且不重叠的源片段。句子重排、多次使用同一句、多源合成和变速均超出范围。先拒绝或标记未支持，再扩展协议；不可把编辑器输出秒数伪装成源视频秒数。所有输出使用统一 fps 与绝对边界取整，相邻区间由边界差得出，避免累积漂移。

ChatCut 的 apply_script preview 验证脚本操作，不是已可播放的合成样片。clean_script 没有 preview 且立即写入；要求先看候选时不能先运行它。用户已授权应用具体计划后，预检通过即可执行，不再为同一个机械 apply 请求一次许可。执行后仍需读回结构并看合成帧、试听切点。

## 4. 人工确认的核心：让用户判断只有人能判断的结果

用户的“人味”不是一个自动评分阈值。相同转录文字，保留一个停顿可能是强调，删掉可能显得着急；“嗯”可能是迟疑，也可能是认可；重复一句可能是失败重说，也可能在建立节奏。视觉方面，色值和尺寸合规仍可能让动画显得卖弄，遮盖真实表情，或者让教程像广告。声音方面，正确音量不保证音效适合说话人的气质。

因此审核要把抽象选择变成可感知的结果。语义删剪至少提供原句上下文、删改理由与可播放的前后对比；动画提供嵌入真实画面的短片；配乐和音效提供带原声的片段；静态排版可先给合成帧，但运动节奏不能只拿截图判断。录屏标注提供落点与关键步骤的真实画面，不能拿独立图形当作证明。

机器先检查文件、时钟、遮挡和基本错误，修好明显问题，再把精炼的小样给用户。不要让用户用一句“同意”批准尚未生成、没有具体范围的效果，也不要让他替机器发现错字、丢步骤和声音错位。

确认有三类，分别记录：

1. **范围授权**：允许处理什么，例如只压缩长停顿、可以修改重复句、允许付费生成或上传指定素材。
2. **结果接受**：用户看过什么，例如此处 cut 前后对比、某个 A 风格动画样片、某个带原声的音效版本。
3. **交付批准**：用户接受哪版 rough cut / final、哪种输出、何处发布。授权渲染与外部公开发布是不同范围。

“允许加动效”不能代替“这个动效效果可接受”；“喜欢 A 风格”也不意味着任何新场景都可以照搬。已接受的风格、组件配方与其适用场景可以复用，内容与落点仍需验证，超出样片覆盖的新效果才重新审。

## 5. 应在哪里停，具体让用户看什么

| 触发点 | 准备好的具体证据 | 人工需决定的内容 | 可以直接继续的部分 |
| --- | --- | --- | --- |
| 审核发现类型、讲解对应或关键数据不确定 | 时间范围、源画面、相邻语音上下文 | 实际讲解对象、真实操作含义、需保留信息 | 继续分析其他确定片段；不猜不确定数据。 |
| 首次选择剪辑强度，或目标变为强压缩 / 重排 / 新开头 | 完整思路的短对比、预计时长与删去内容 | 是否仍像自己的表达，保留什么，是否接受叙事变化 | 已有授权范围内的候选提取和隔离草稿准备。 |
| 语义删剪存在不确定性 | 同一语义范围原版 / 精修版，包含自然前后余量 | 重复是否故意、转折 / 限定词能否省略 | 已明确授权的纯机械处理，不对每个口癖单独询问。 |
| 初次确定口播剪后节奏 | 一小段能试听的剪后样片 | 是否过快、失去呼吸或变得拼接感明显 | 样片接受后在同类片段按相同规则执行，仍检查异常。 |
| 新视觉语言或显著改变组件 | 真实口播上完整出现与退出的短片，必要时两版 | 信息是否自然、是否遮脸、视觉是否抢过讲述 | 复用已批准 A 风格，无需重新问深色底；已明确偏好直接执行。 |
| 新 B-roll、插图或事实画面 | 带前后口播的实际位置、素材来源与拟表达关系 | 是否贴题、是否有误导、是否像该创作者 | 录屏“不加 B-roll”直接复用；不同用途的圈画 / 放大独立判断。 |
| 首次配乐或明显音效策略 | 带原声的短片，含实际进入 / 退出和音量 | 气质与密度是否合适，是否抢话 | 已批准稀疏策略内同类提示点机械放置。新情绪、夸张音效另审。 |
| 录屏缩短等待、局部放大或步骤重排 | 点击前、点击时、结果后的连续可播放片段 | 是否仍能跟做，步骤与说明是否匹配 | 单纯分辨率、位置或编码调整在既有授权内执行。 |
| rough cut 完成 | 完整可播放版、必要的章节位置、尚未处理事项 | 内容、自然节奏、教程完整性是否通过 | 内容接受前不大规模堆后续特效；可并行做不依赖切点的素材准备。 |
| final 完成 | 完整带声合成版、输出规格与已完成检查 | 是否交付这版，是否还有具体修改 | 已授权的格式转换、导出、交付可执行；公开发布无授权时单独处理。 |

这些是条件检查点，不是每条视频都执行整张表。只做字幕的任务无需走配乐审片。已审核的小样可覆盖同一配方的批量工作，不把十处同类标注拆成十次确认。ChatCut 口播技能要求主要步骤确认；总插件应在真正的内容 / 视觉 / 声音步骤输出具体审片结果，而非工具调用间停顿。若用户明确要求全流程不停，可在其授权范围内执行；语义不确定时保守保留，实际超出授权的上传、收费或公开发布仍不得推断为获准。

## 6. 确认记录必须带对象和版本

未来新增 review request 与 approval 两种记录。一个待审请求至少包含：项目、原因、可感知的问题、输入版本、拟执行范围、受影响片段、实际小样路径 / URL 与哈希、推荐选择及其他可行选择。前后对比还要明确哪个是原版、哪个是拟用版本。缺证据时状态应为 evidence_pending，不生成空的“请确认”任务。

结果记录包括同意 / 要修改 / 保留原版、用户原话、所看的产物哈希、批准的配方 / 片段 / 整片范围及时间。推荐值、用户沉默、文件已生成、工具成功返回和旧版本批准都不等于新批准。

授权可以长于某一个产物，例如已明确“录屏不加 B-roll”；这类偏好记录范围和来源，直接复用。结果接受则绑定看过的版本，例如“这版口播节奏可以”。二者不能合并成一个 confirmed 布尔字段。

流程状态建议为：审核素材 → 获得相关范围授权 → 准备候选和小样 → 自检 → 待审 → 应用批准范围 → 再次验证 → 阶段完成。人工待审只阻止依赖该结果的工作，其他独立工作仍继续。审批通过还需适配器实际能力验证，不能直接放行不可用工具。

## 7. 修改只使相关批准失效

每次修改应列出依赖关系，而不是重问全部偏好。

- **修改删剪结构**：受影响范围之后的时钟映射、字幕落点、动画、B-roll、音效及音乐长度需重算。节奏审片、rough cut 和 final 相关批准失效；品牌风格与录屏不加 B-roll 偏好继续有效。
- **修字幕文字**：对应字幕和含该字幕的合成片段需重看。仅错字修正通常不要求再审整段口播；更改数字、单位、结论、条件或品牌名时先核实来源。不得同步篡改原声。
- **换一种动画或配乐**：对应效果样片和 final 需重新接受；已通过的内容结构保持有效。
- **修改真实数据、按钮或步骤**：受影响教程范围和说明一起核验，再更新对应审片。不能先让错误画面进入成片，再靠用户兜底。
- **纯编码变化**：重新做媒体、字幕可读性和音频一致性检查。内容不变且可证明时，不要求再次审美确认。

依赖应按实际内容版本与时间映射判断。剪掉片段导致后续时间变化时，人工反馈引用的“第 20 秒”需重新绑定原语义范围，避免修改了错误位置。

## 8. 当前实现的缺口与落地顺序

现有 intake 能按分类生成问题、复用明确偏好，但所有可达的未答键都 required，语义剪辑只有 preserve / review_trim，音效只有 none / subtle / expressive。它没有具体候选、小样产物、用户接受范围、时钟依赖和局部失效机制。下一阶段应扩展这些能力，不能只把 ChatCut 加进 registry 就称为完整插件。

建议按以下顺序落地：

1. **诊断与路由**：只读确认连接、可用工具、实际项目和能力，区分“未发现”“已连接未验证”“短样通过”。无法连接时保留当前本地路线，不重装、重复登录或私自上传。
2. **审片协议与状态机**：将授权与效果批准拆开；为真实产物建证据、版本与依赖记录。先验证“不重复确认已授权动作”“旧样片不能批准新版”“局部修改只失效相关项”。
3. **最小 ChatCut 精修试验**：在隔离项目用非敏感短样压缩一个明确停顿，读回结构、试听并看字幕。连接可用仍不代表用户已授权上传当前个人素材或生成收费内容。
4. **时钟交接**：读回实际源 / 输出片段，处理 fps、转录版本和词锚点。若无法可靠归一化，先限制在 ChatCut 单编辑器闭环，不向剪映 / Remotion 自动双写。
5. **视觉与声音扩展**：复用 A 风格先做一个真实片段；人工接受后才铺开同类效果。声音保持单独可听小样与来源记录。
6. **完整交付验证**：区分 MP4、字幕、XML、透明图形与剪映可编辑草稿。目标编辑器必须实机播放、保存重开和导出验证，再升级能力状态。

## 9. 最容易造成虚假完成的风险

- “ChatCut 支持某能力”被误写为“当前 Codex 能调用并已验证”；插件安装、账号登录和会话工具暴露是不同层。
- “精修”被误解为允许强删、重排和重新组织作者观点；重复不是当然可删，词时间也不是完美切点。
- 先加动画与字幕再剪人声，或只相信同轨 ripple；其他轨道和教程画面未必自动同步。
- 把语音编辑的 dry-run 当作可听可看的效果审片；用户批准了文字，但尚未判断自然节奏。
- 自动转录器覆盖手工修正文本；两个 word ID 系统被混用，或把输出时间当成源时间。
- 为“统一插件”同时同步两套活跃编辑器，最后不知道哪份才是已批准成片。
- 将 XML、烘焙视频或一个透明 MOV 描述为完整可编辑剪映工程。
- 将图片无误、时长正确、导出成功或测试通过描述为审美批准；机械证据与人的接受必须分开。

最小成功标准是：用户看过一个真实、带原声的剪后片段并接受自然节奏；我们能读回这一剪辑的实际时间映射，在同一当前主时间线上完成字幕与效果，并在修改后准确指出哪些内容需要重审。做到这一步，比一次接入所有引擎更接近完整插件的核心。
