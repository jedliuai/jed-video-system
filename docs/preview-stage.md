# 第一轮视觉与插件原型

日期：2026-10-01。用户已授权制作样图 / 短视频，再逐步整合为完整插件。本轮不是完整成片自动化的验收。

## 视觉产物

18 秒样片：1920×1080，30fps，540 帧，H.264，无音频。口播观点、比较图表、教程录屏各 6 秒，使用同一 Remotion 组件实现静帧和视频。

原始导出视频采样 0.6 秒口播帧与 25 秒录屏帧，作为静态背景。最初口播采样 5 秒；去掉遮罩后会露出原片已有的“私信我”包装，所以换为没有该侧栏的早期帧，未抹除或篡改原片。动画按帧驱动，观点按 cue 出现；示例文案未对齐原讲述，图表数据为已标注的示例。原片字幕、人物圆框和角标是烘焙内容，当前不重复添加字幕。下一轮必须使用未烘焙素材或明确保留这些已有元素。

A 版以深蓝、品牌蓝、金色为重点色，建立左侧观点层、全屏比较与教程步骤三种场景。另一版口播由 agy 实际评审给出版式规格后实现；设计来源见 `design/agy/status.md` 与 `review-followup-response.json`。原先 Codex 的备选版保留在独立文件，不混淆来源。

用户看过样片后明确选择 A，并要求口播不要深色底，元素直接呈现在画面上。正式 A 已移除全部全屏底色与渐变遮罩，使用深色正文、品牌蓝强调与轻微文字阴影；观点仍按同一 cue 累积出现。章节未激活编号也改为透明底。`config/visual-preferences.json` 保存这个方向供后续 planner 读取；当前 Scene 已按该选择实现，尚未有运行时配置 compiler。

## 本机环境与运行

Remotion 初次安装 4.0.531；渲染可用，但 Studio 首页报 `getRenderQueue is not a function`。检查本地文件与从 npm 获取的同版本发布 tarball，二者 `dist/render-queue/queue.js` 均为 0 字节。没有补写第三方源码，改为统一锁定已在本机其他项目使用的 4.0.530，并重新验证预览和导出。复用现有 Jed 字体和已安装的 Chrome headless，不重新下载浏览器。本机路径在忽略的 `scripts/preview-local.json`，公共脚本不写死用户机器路径。

agy 的 CMD 入口与 PowerShell 入口指向同一可执行文件。应用内终端没有继承本机 Clash 的代理；补充调用进程的代理变量后，现有登录可复用，无需再次认证。认证码不进入文件或日志。

Studio 可逐帧预览，静态页面可直接播放样片、切换口播样图。当前 Codex 内置浏览器桥接不可用，无法进行应用内浏览器交互验收；以实际静帧检查、源检查和导出视频元数据验证为本轮依据。

最终检查通过：ESLint、TypeScript、17 个 intake 行为测试；四份 intake Schema 与示例输入输出校验。18 秒与 6 秒视频分别有 540 / 180 帧，均完整解码通过。实际静帧和每秒连续采样检查了观点出现、图表增长与步骤推进。Studio、预览页和全部展示素材返回 HTTP 200。

## 下一步

口播方向已选定为原画面上直接呈现 A 版元素。下一步将观点 cue 与真实转录词时间对齐，做一段带原声音的片段。再把同一组件渲染为独立素材，接入剪映副本草稿并验证保存重开。客户 intake 与这些制作 adapter 保持独立，避免视觉调整牵动转录或草稿逻辑。
