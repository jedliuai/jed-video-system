# 第二轮：真实口播到独立剪映草稿

日期：2026-10-01。用户已授权继续，沿用A版原画面叠层、录屏不加B-roll。当前阶段完成的是本机人工计划闭环，尚未宣布全部插件生产能力完成。

## 看结果

`work/previews/jed-live-preview.mp4` 是40.8秒、1920×1080、30fps、1224帧的真实视频，保留原声和完整讲述。口播分源码获取与实机演示两个模块，要点按真实词时间出现并保留到模块结束；透明层在11.6秒前退场，约11.8秒切入录屏，之后不加新B-roll或标注。字幕来自正式草稿里人工修正的16条文字，不用ASR错字覆盖已有版本。

剪映首页工程 `jed-probe-live-20261001-a726bdf2` 是新建的隔离副本：一条原声底片轨、一条0–11.6秒的ProRes 4444透明动效素材轨、16条独立可编辑字幕。图形内部文字仍属于渲染素材，通过props重新生成；不要把“透明动效轨可调整”理解为其中每个图形都是原生剪映对象。正式旧工程未写入。

## 同一时间计划

1. 既有Video Use helper在本机GPU上转录根目录样片，40.8秒、231字/词，耗时35.67秒。缓存按源SHA、配置、helper哈希、runtime版本分开；真实复用成功，没有重跑ASR。
2. 源草稿指向包装片98.45秒起的40.783333秒；读取其精修脚本找到了没有左侧提示与字幕的原底片。按相同范围提取为30fps的 `live-source.mp4`，原有Jed Liu署名保留。
3. ASR实际输入与新底片的hash分别记录。三个音频窗口相关性0.9933–0.9992、偏移均为0，证明它们在本轮范围内共享人声时间。这个检查不能替代逐字人工试听。
4. `work/plans/live-edit-plan.json` 是依据已有会话授权写的人工计划，不是从尚未回答的intake自动生成的计划。保留完整人声，不新增音效或库存B-roll；未把这些本轮操作升级成客户长期偏好。
5. `compile_plan.py` 用词ID和源秒时间编译统一帧props，先各自取整边界再相减，支持30/60fps、仅1倍速。预览、透明层与草稿都消费同一结果。

两个动效窗口是0–204帧、204–348帧。标题和要点分别使用实际词anchor，质量与是否近似保留在 `timingReview`；没有宣称自动对齐等于逐帧真值。无重新删句、变速或生成配音。

## 音频导出校正

首次Remotion原声导出完整解码可用，但相关性检查发现固定延后0.0426875秒，超出30fps的一帧。保留未校正文件，按三个窗口的共同偏移量只校正音轨，并复制视频流，未再次编码画面。最终文件40.800000秒，三个窗口均回到零偏移，相关性0.9883–0.9956。

`normalize-preview-audio.py` 不盲目写死43毫秒。它每次测量共同偏移，出现低相关性、变化漂移或过大延迟时拒绝自动校正。当前只适用于该单段连续原声；多段真实精修以后需要按输出时间拼接校验基准。结果在 `work/manifests/preview-audio-correction.json` 与 `preview-audio-alignment.json`。

## 重现入口

公共字段模板是 `config/local.example.json`，本机绑定写在忽略的 `config/local.json`。在项目根依次运行：

```powershell
pwsh -File scripts/prepare-live-source.ps1
pwsh -File scripts/render-live-preview.ps1
pwsh -File scripts/create-live-draft.ps1 -Publish
```

最后一条不带Publish时只隔离保存；登记时仍由已有Bridge检查软件运行状态、锁和索引备份，不强制关闭剪映。每次创建新的唯一工程，不覆盖原工程或重复使用旧副本名称。

本轮实际试跑了不带Publish的统一入口，成功返回隔离草稿及 `Published: False`，没有再添加首页记录；其调用证据保存在 `work/compatibility/jed-probe-live-20261001-fa8477c4-result.json`。

本轮编译器、转录器、问询模块是插件内的独立模块；渲染与draft worker通过本地配置绑定现有能力。原始个人素材、输出、字幕实际内容、本机路径和缓存都保留在工作区，不进入公开示例。当前包仍需要该工作区，不是完成的跨机器独立安装产品。
