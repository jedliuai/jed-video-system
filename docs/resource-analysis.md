## 2. UP 的视觉结构

### 顶部章节导航

01—08 小方块一直提供章节上下文，已完成项、当前项和未开始项各有状态。下方是小型英文分类条与中文重点标题。这值得独立做成 `ChapterProgress`，章节数量由数据决定，不固定写死为 8。

### 两侧信息，中央人物

图表、数字和引用尽量在左右侧构建，人物仍是叙述中心。卡片常用透明 / 深色底、细边框和有限的发光；大数字和关键结论经常直接放在背景上。并不是每句话都包进一个大卡片。

### 少量有语义的颜色

蓝色承担 AI、主数据和当前章节；金色承担人脑、对照项或关键结论；红色承担损失、浪费和异常。文字层级由尺寸、字重与位置形成，英文小字和来源信息辅助可信度，不抢主结论。

### 信息图叠在不同底片上

相同章节栏、标题、卡片和图表可以叠在真人口播上，也可以叠在影视感较强的素材画面上。这支持把 B-roll 底片和确定性的图形分开管理；不能从最终成片反推这些画面一定由 Remotion 制作。

## 4. 你的实拍案例给出的约束

[实拍采样](research-media/personal-contact.jpg) 中，前段是真人口播，后段是大屏幕窗口、右下圆形人物与深蓝背景。这个结构适合固定的 `ScreenDemoFrame` Scene。

真人前段的背景比 UP 更亮，人物更大，手势也会占用中下部。因此不能照搬参考片的两侧宽图表：需要人物保护区、字幕保护区，且卡片有深浅背景两种固定表面样式。

案例左上较小的青色字和细线，在缩小画面后可读性偏弱。新库应优先改善中文字重与字号；保留简洁感，但不用过小标签承担关键结论。

当前案例已经有可见字幕与姓名。查看其对应剪映草稿时，又读到单独的文字轨道。若直接拿这条 MP4 再加一层字幕，可能出现重复。初次真实生产应使用原始口播与录屏，或明确选择继续编辑现有草稿；这份案例首先用于布局验证。

还有一处要记录：对应草稿是 60fps、40.783333 秒，案例 MP4 是 30fps、40.800 秒。源片、草稿、导出文件必须分别记录时间基准，不用文件时长浮点数推断草稿最后一帧。

## 5. 推荐视觉方向：Jed 的蓝色信息系统

建议继承参考片的信息层级、逐层建立和两侧布局，结合现有 Jed Logo 与深蓝屏幕演示背景，形成自己的主题。以下值是第一版设计提案，不是对参考图的精确取色。

| Token | 建议值 / 原则 |
| --- | --- |
| 主强调色 | `#2D6BFF`；与 Logo 蓝点建立联系 |
| 对照 / 结论色 | `#F5B642`；同一个 Scene 内语义保持一致 |
| 异常色 | `#F04452`；只表达损失、警示或负向差异 |
| 深背景 | `#081224`；沿用 Jed 已有深蓝方向 |
| 主文字 / 次文字 | 深底 `#F7F9FC` / `#A8B4C7`；亮底使用深色文字 |
| 表面 | 深色半透明卡片或亮色文档卡片；禁止临时换第三套主题 |
| 字体 | 优先复用本机 Noto Sans SC 静态字体资源；正文与标题固定字重 |
| 字号基准 | 1080p：正文 32—40px、重点 48—64px、大数字 80—112px；手机缩小检查后定稿 |
| 圆角 | 小标签 10px、信息卡 16px、截图窗口 20px |
| 边框 / 阴影 | 1—2px，弱阴影，重点才用微弱发光 |
| 间距 | 8px 基础单位；尺寸、对齐与基线统一 |
| 动画 | 入场 0.2—0.4 秒；图表展开 0.8—1.2 秒；同组 stagger 0.1—0.2 秒 |

动画参数是起点。默认缓出、不用明显弹跳；数值单位静止，数字定宽，条形图长度随数值比例变化。逐词 cue 控制何时讲到下一项，固定 motion preset 控制每项怎么进入。最终画面一般至少留 1 秒阅读时间，不把所有组件压成一秒闪过。

字重经验可以从已有口播项目复用：此前 Noto Sans SC 可变字体默认落到很细的字重，已有项目生成过 450 / 650 静态实例。需要检查实际字体文件与许可，再选定一组；本轮没有新增或安装字体。

透明素材只能包含它自身的底板、边框和阴影。若没有将真人底片输入同一次渲染，预渲染透明卡片无法对剪映里的底片实时做真正的毛玻璃背景模糊。第一版用半透明深底解决可读性，避免视觉承诺超出交付格式。

## 6. 布局和信息密度

第一版以 16:9 为主；新建项目默认 1080p/30fps，已有工程继续使用其实际 fps。60fps、4K 作为配置能力，不因为参考片是 4K 就强制每段都输出 4K。

| Scene | 推荐用途 | 重点 |
| --- | --- | --- |
| TalkingHeadInsight | 真人口播＋一个观点 / 数字 | 保持人脸和字幕净空 |
| TalkingHeadComparison | 真人口播＋侧边图表 | 图表先建立，再落结论 |
| EvidenceExplainer | 底片＋来源截图＋数据 | 证据、数字、结论明确对应 |
| ScreenDemoFrame | 软件大窗口＋圆形人物 | 沿用案例布局，界面保留尽可能多的可读面积 |

16:9 初始保护区可以用中央约 40% 的人物区域与底部约 16% 的字幕区域起步，再按真实镜头修正。宽折线图更适合全屏解释或专门的宽图表布局，不能机械叠在人脸上。

9:16 需要自己的纵向布局，不是把 16:9 整体缩小。第一阶段不同时追求所有比例，以免 Gallery 验收目标失焦。

## 7. 不应该照搬的部分

不使用 UP 成片里的播放器控件、作者标识和具体研究数字作为 Jed 生产素材。参考图上的 FLOP、token、论文结论只作为视觉观察对象，本轮没有核验这些主张。

截图引用保留标题、来源、日期和 URL；若数据缺来源，planner 给出待补来源，而不是根据条形图好看程度编造数值。文档截图尺寸固定，但具体内容和图片均通过 props 替换。

Logo 现在有白底。后续需要独立准备透明深/浅两版品牌资产，之后才用于角标；不会在本阶段擅自重画 Logo。
