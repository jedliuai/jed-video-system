# 路由与人工审片

总插件只保有自己的意图、计划、能力证据和审片记录。外部工具按需使用；没有工具时报告准确的缺项，不重装所有插件或重复登录。

## 路由

`scripts/route.py --request examples/route-request.json --capabilities examples/capabilities-unconnected.json`只读输入，输出路由与待准备的小样要求；此示例明确全部未连接，应退出2。退出0仅表示请求的后端功能已在输入快照中登记，`executionAuthorized`始终false。

`destination`决定主编辑器及交付对象，支持jianying、chatcut、preview。每环节单独检测能力，缺功能不悄悄换编辑器。`motionMode=fixed`选Remotion，`editable`可选已连接ChatCut图形；跨编辑器需独立的媒体/透明层交接证据。

能力JSON不是身份认证，也不代替实际工具发现。公共示例全未连接；测试中的connected=true仅为合成fixture。读取快照后，实际调用前刷新目标项目、素材及受影响时间线。未验证的转录导入、源时间读回、图形导出或剪映UI验收保持blocked。

## 何时让人看

先继承用户明确偏好，再识别新的语义、视觉、声音决定。审片不是一份固定问卷：只修字幕的任务不需要音乐审片，格式转换不需要重新选风格。存在新的运动节奏、叙事、表情覆盖或情绪改变时，先做真实短样。

- 语义：展示原句及前后语境、删改理由、可试听的拟用版本。限定词、转折、刻意重复与演示等待不能机械删除。
- 视觉：在实际底片上看入场、阅读时间、退场；检验遮脸、字幕冲突与讲述是否被抢走。已有A风格可复用，新组件仍可能需要第一次小样。
- 声音：带原声听音效密度、实际音量、音乐进入/退出；静音画面或纯音效无法证明是否适合口播。
- 教程：连续看操作、结果及讲解。录屏不加B-roll独立于圈画/缩放；步骤和事实正确性由机器先检查，不把明显错误交给客户兜底。
- 整片：rough cut看内容与节奏，final看组合效果和交付版；仅当新变化或用户明确要求审片时触发，不把已授权导出当作再次许可问题。

## 状态与范围

`suggest_gates`只建议需要的小样，没有具体产物则prepare_sample，不创建假批准。候选经自检并展示后才能申请审核；pending、reject、revise都不会放行。用户选择由host从明确回复录入，CLI记录本身不能验证用户身份或是否已观看。

授权处理一个范围和接受某个效果是不同记录。机械处理可由明确项目授权直接放行；审美批准则绑定scope/subject、修订、操作版本、范式和样片摘要。局部变化只使对应及依赖记录失效，保留未受影响的偏好和批准。批准一个例子不代表对其他片段、新配方或新版的无限授权。

外部调用只有在intake约束、工具能力、当前操作授权、相关小样批准及工具自身检查同时满足时执行。机器的结构/媒体检查与人的效果接受分别存储。实际剪映播放、保存重开和原生导出也独立于生成草稿成功。

上述小样批准针对正式应用与批量扩展，不阻止已授权的隔离样片准备。窄任务只检查本次相关的约束，不能强迫填完整intake问卷。回复记录必须绑定当时展示的requestId；旧请求过期后收到“同意”不能自动挪给最新请求。

0.5包含两项受控本机动作，操作步骤见 [dispatch.md](dispatch.md)，章节候选和已确认配方的本机交接见 [chapters.md](chapters.md)。仍没有通用外部调度器；其他旧渲染/草稿入口必须由使用总skill的host在调用前检查。接入ChatCut后先验证一处停顿及字幕同步，可靠时钟交接之前不自动双写两个编辑器。
