# 第一轮样片和客户问询跑起来了

**做了什么**

今天把前面的资源调查推进成了能看的结果：用 Remotion 做出口播观点、比较图表、教程录屏三种场景，导出一条 18 秒 1080p 样片、四张样图，以及一条 6 秒的 agy 口播备选。做了本地预览页和可重现的素材准备、渲染脚本。视觉组件、文案数据和品牌 token 分开，后面换内容不用重做布局。

另外搭了统一插件的第一版骨架，把素材审核后的客户问询独立做成纯 Python 模块。现在可以根据片段分类、项目答案和明确用户偏好，决定下一步该问什么。剪映、转录、音效等生产 adapter 的状态都写清楚了，没把骨架说成完整生产系统。

**为什么做**

用户希望先看真实效果，再把剪映 MCP、CLI、Remotion、音效、口播精修和 Video Use 逐步融合成一个完整插件。模块多，所以这次让不同子 agent 分别做 A 版视觉、agy 视觉评审和 intake，总控负责接起来、渲染和验收。先验证视觉和问询，比一开始就铺满所有接口更容易知道方向对不对。

**值得记住的决策和坑**

用户看过后选了 A，但明确不要深色底，要让元素直接出现在真人画面上。最终 A 去掉了全屏底色和所有渐变遮罩，改为深色正文、品牌蓝强调和轻微文字阴影。这个方向保存到了 visual-preferences。最初用了 5 秒的底片，去掉遮罩后会露出已经烘焙在原视频里的“私信我”，于是改用 0.6 秒没有这个侧栏的采样帧；没有去抹原画面。现有字幕和角标也已经烘焙，正式剪辑时需要注意避免重复叠加。

样片背景还是静态帧，动画是真实渲染，但没有对齐讲述、没有音频；图表数据是注明用途的示例。下一段工作是让这套组件跟真实口播时间同步，然后验证独立动效进入剪映副本草稿。

agy 原来就在用户 CMD 里可用，应用终端没有带上 Clash 代理才误报需要认证。仅给调用进程补代理后，复用了现有登录，拿到了真实评审。第一次设计调用超时返回空 response，虽然退出码是 0，也不能当作设计成功；续同一会话才拿到非空规格。备选版按这些规格实现，保留来源记录。

Remotion 最初的 4.0.531 可以渲染，但 Studio 首页出错。本地和 npm 发布包里的 queue.js 都是空文件。没有去补写第三方文件，而是统一锁到本机已用过的 4.0.530，Studio 恢复正常。Chrome 也复用现有 headless 程序，避开重复下载。

客户偏好只保存已经说清楚的选择：录屏 B-roll 为 false。项目答案可以覆盖长期偏好，建议值不能冒充确认；不加 B-roll 也不等于不能加圈画、缩放和步骤提示。缺少必需答案时不产出制作意图，分类不可靠时先确认分类。口播要不要 B-roll 仍要问，不能因为“通常只放口播”就默认每段必须放。

验收结果：17 个问询行为测试通过，四份 Schema 和示例输入输出校验通过，ESLint 与 TypeScript 通过。最终两个视频分别是 540 帧 / 18 秒和 180 帧 / 6 秒，均为 1080p、30fps、H.264，完整解码通过。看过静帧和连续采样，人物脸部、原有字幕和录屏内容保持可见。预览页、素材链接和 Studio 均返回 HTTP 200。应用内浏览器桥接不可用，这轮没有假称做过完整浏览器交互验收。

**一句话亮点**

让 AI 剪辑先学会看素材、记住你的习惯，再用同一套视觉组件把讲述变成画面。
